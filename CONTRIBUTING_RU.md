### 🎯 Цель
Опишите общую картину ваших изменений здесь, чтобы объяснить мейнтейнерам, почему стоит принять этот Pull Request. Если это исправление ошибки или добавление функции, обязательно укажите ссылку на соответствующую задачу.

### 🛠 Детали реализации
Опишите детали реализации для этого Pull Request.

### ✍️ Объяснение на примерах
Объясните примеры с кодом для этих обновлений.

### 🔠 Именование pull request'ов
1. Если это новая функция: [feature/*]
2. Если это исправление ошибки: [bugFix/*]
3. Если это обновление документации: [documentation/*]

### Подготовка pull request'а к обзору
1. Перед отправкой изменений убедитесь, что выполнили **"./gradlew ktlintCheck --continue"**. Если есть ошибки lint, исправьте их до создания pull request.
2. Ваш pull request должен пройти `CI workflow` перед запросом обзора у мейнтейнеров, если нет — исправьте проблему.
3. ♻ Всегда создавайте новую ветку от `develop`.
4. 🚨 Всегда создавайте pull request в ветку `develop`.
5. Всегда используйте информативные сообщения коммитов, объясняющие изменения.
6. Всегда добавляйте описание к pull request, подробно объясняющее, что вы сделали. Желательно прикладывать запись видео или скриншоты, если возможно.
7. Если нужна помощь с вышеперечисленным, не стесняйтесь обращаться ко мне, я помогу.

## Проверка кода
Все изменения, включая изменения от членов проекта, требуют обзора. Для этого мы используем GitHub pull requests. Дополнительную информацию о работе с pull request'ами можно найти в разделе [GitHub Help](https://docs.github.com/ru/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/about-pull-requests).
